# ★★★ 历史坑（务必牢记）★★★
#   `rescue/partition-split.txt` 里每一项都比真实值 **多 8192 扇区 (4MB)**，不可用于 wl！
#   用它刷会导致镜像从分区内 +4MB 处开始写、尾部溢写覆盖下一个分区 —— 这正是
#   2026-11-10 砖机的真正原因（不是 dm-verity）：
#     wl 40960(resource)  尾部 4MB 溢出 -> 覆盖 kernel 分区前 4MB
#     wl 811008(system)   尾部 4MB 溢出 -> 覆盖 metadata/verity_mode/baseparamer/frp
#
# ★ rkdeveloptool 的 `wl <BeginSec>` 的 LBA 单位 = 全盘镜像内的字节偏移 / 512，
#   与 `wl 0 全盘镜像` 的坐标系一致（该操作已实测成功救砖）。
