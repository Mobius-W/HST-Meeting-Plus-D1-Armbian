# 麦阵 ES7243 驱动 —— 2026-11-17 第二轮进展（MCLK 破案 + 软件侧穷尽）

> 承接 `麦阵-ES7243驱动-进展与待办-20261116.md`。
> 本轮解决了一个此前一直误判的关键问题（I2C 不通的真因），并把芯片型号、寄存器模型完全钉死；
> 但 **SDOUT 仍然恒高**，软件侧已无可调项，剩下的是硬件层。

## 一、★ 关键突破：I2C NAK 的真因是 MCLK 没真正输出

### 症状
`mid_hw_params` 里写 `0x00=0x01` 返回 `-6 (ENXIO)`，`i2cget 0x10` 全部 NAK，
`i2cdetect -y 1` 一个设备都扫不到（连 0x11 都没有）。

### 真因（两条，叠加）
1. **`clk_prepare_enable()` 不等于有时钟输出**
   `devm_clk_get(dev, "mclk")` 拿到 `clk_i2s0`，只 prepare+enable 时 `clk_summary` 显示
   `clk_i2s0_mux enable_cnt=1 rate=0` —— **rate 是 0，引脚上没有波形**。
   必须再 `clk_set_rate(clk, 12288000)` 才真正落频。
   （之前偶尔能看到 `mclk 12288000 Hz` 是上一轮录音残留的 rate，重启后就是 0。）
2. **ASoC 的调用顺序对 codec 不利**
   `__soc_pcm_hw_params()` 里 **codec 的 hw_params 先于 cpu dai 执行**，
   而 `rockchip_i2s` 的 `i2s->mclk` 只在 `i2s_runtime_resume()` 里 enable
   ⇒ codec 写 I2C 那一刻 i2s 的 mclk 未必已开。

### 修法（已落地，commit 4e69ef3）
- DTS `mic-array` 节点加 `clocks = <&cru SCLK_I2S0_8CH>; clock-names = "mclk";`
  （`SCLK_I2S0_8CH` = 86 = 0x56，与 dtb 里 `clocks = <0x08 0x56>` 一致）
- probe 里 `clk_set_rate(12288000)` + `clk_prepare_enable()`，**常开**
- `adc_power_up()` 里再按 `priv->mclk` 兜一次 + 20ms 等待
- `adc_write()` 加 5 次重试（间隔 2ms），应对时钟刚起时的瞬时 NAK
- 板端 DTB 用 `tools/patch-dtb-micarray.py` 手术（脚本已改成幂等：已存在 mic-array 时只补 clocks）

### 验证
`insmod` 后 dmesg `mclk 12288000 Hz enabled`，`clk_i2s0` rate=12288000、consumer=mic-array，
`i2cget 0x10 0x00` 立刻能读到值。**这条通了。**

## 二、★ 芯片型号钉死：是 ES7243（16 寄存器，非 E 版）

拿到真正的 **ES7243 datasheet（Rev 11.0 / Rev 3.0，17 页）**，寄存器默认值与板端实测逐项吻合：

| 寄存器 | datasheet 默认 | 板端实测 | 结论 |
|---|---|---|---|
| 0x00 MODE CONFIGURE | 0x00 | 0x00 | ✓ |
| 0x01 SERIAL DATA PORT | 0x00 | 0x00 | ✓ |
| 0x02 LRCK DIVIDER | 0x10 | 0x10 | ✓ |
| 0x03 BCLK DIVIDER | 0x04 | 0x04 | ✓ |
| 0x04 CLOCK DIVIDER FOR ADC | 0x02 | 0x02 | ✓ |
| 0x05 MUTE CONTROL FOR ADC | 0x13 | 0x33 | bit5 只读 |
| 0x06 STATE CONTROL FOR CHIP | 0x00 | 0x00 | ✓ |
| 0x07 ANALOG CONTROL 0 | 0x80 | 0xDC | bit6/4/3/2 状态位 |
| 0x08 ANALOG CONTROL 1（增益） | 0x11 | 0x11 | ✓ |
| 0x09 ANALOG CONTROL 2 | 0x80 | 0x00 | **≠ 默认** |
| 0x0A ANALOG CHARGING PERIOD | 0xC0 | 0xC0 | ✓ |
| 0x0B DIGITAL INITIATING PERIOD | 0xC0 | 0xC0 | ✓ |
| 0x0C DIGITAL INITIATING PERIOD | 0x12 | 0x12 | ✓ |
| 0x0D CHIP STATE AND OSR | 0xA0 | **0x60** | **bit7=0 ≠ 默认的 1** |
| 0x0E CHIP ID | 0x40 | 0x40 | ✓ |

⇒ **确认板上是 ES7243，不是 ES7243E**（E 版寄存器表完全不同：0x03 默认 0x20、0x09 默认 0xC1…）。
⇒ 16 寄存器版本，**不存在 0x10~0x18 那些 ANALOG 寄存器**，ES7243E/ES7243L 的序列不能照搬。

## 三、★ 已穷尽的软件手段（勿重复）

| 实验 | 结果 |
|---|---|
| 原厂 11 写序列（0x06=18,01=0c,02=10,03=04,04=02,05=1a,08=41,07=80,09=00,06=00,05=13） | SDOUT 恒高 |
| ESP-ADF 6 写序列（seq_variant=1） | SDOUT 恒高 |
| 只写 0x00=0x01（seq_variant=2） | SDOUT 恒高 |
| 驱动完全不碰芯片（seq_variant=3）+ 手工配 | SDOUT 恒高 |
| 0x00 逐位扫描 0x01/02/04/08/10/20/40/80/FF | 只有 bit0~6 可写，**bit7 恒读 0**；数据不变 |
| 0x06 扫描 0x18/08/10/03/0C/30/C0 | 写入生效，0x0D 恒 0x60，数据不变 |
| 0x07=0x80（关 bit4，语雀称 bit4=1 会关 SDOUT） | 写入生效，数据不变 |
| 0x09=0x80 / 0x00 | 无差别 |
| 采样率 8k / 16k / 48k（MCLK 2.048M / 4.096M / 12.288M） | 无差别 |
| 声道 2 / 4 / 8（RXCR CSR=0/1/3 均已确认写入） | 无差别 |
| TRCM_TXONLY / TRCM_TXRX（CKR bit28 = 1/0 均确认） | 无差别 |
| bclk_ratio = 32×ch（64） | 无差别 |

## 四、★ 决定性证据：芯片停在未上电状态

- `0x0D CHIP STATE AND OSR` **恒为 0x60**（datasheet 默认 0xA0）。
  bit7 = 0 ⇒ 芯片状态机没走到"运行"。
- `0xFD/0xFE/0xFF` = `0x60/0x40/0xFF`，**录音前后完全不变**（没有任何时钟检测/就绪标志翻转）。
- `0x00` 的 **bit7 写不进**（写 0x80 读 0x00，写 0xFF 读 0x7F）⇒ CSM 上电位不在 bit7，
  或该位只读。ES7243L 笔记里"运行 slave = 0x00=0x80"的写法在本芯片上不成立。

SoC 侧同时刻全部正常：
- `clk_i2s0` = 12.288MHz enabled，consumer = mic-array
- `I2S_CKR` = 0x10033f3f / 0x00033f3f（TRCM 两种都试）
- `I2S_XFER` = 0x3（TXEN + RXEN 都在）
- `I2S_RXCR` = 0x0f（2ch/16bit）/ 0x0001800f（8ch，CSR=3）
- pinctrl 9 脚全在 `i2s0-8ch-bus`（含 gpio4_A0 = MCLK，func1 = I2S0_MCLK 已查证）

⇒ **SCLK/LRCK 由 SoC 输出、RX 用它们采样 SDI，读到的 `0xFFFF` 就是 SDI 线的真实电平**
⇒ SDI 线没人驱动 ⇒ **ES7243 的 SDOUT 一直是高阻**

## 五、当前判断与下一步

### 判断
软件侧（SoC/DTS/驱动/寄存器）已经全部对上了，问题在**芯片侧不出数据**。
最可能是：**ES7243 的模拟供电（VDDA，pin12）或 IO 供电（VDDP，pin1）没到**，
或者 SDOUT（pin3）到 SoC SDI0（GPIO3_D3, pin123）的走线有问题。

依据：I2C（数字域，VDDD/VDDP）完全正常、寄存器可读写 ⇒ 数字部分有电；
但 chip state 不推进、SDOUT 高阻 ⇒ 模拟域没起来。
（ES7243 无 CE/PDN 引脚，无法用 GPIO 关断，只能靠寄存器；而所有寄存器组合都试过了。）

### 需要硬件确认（按优先级）
1. **量 ES7243 pin12 VDDA 对 pin13 GNDA 电压**（应为 3.0~3.3V）；pin1 VDDP、pin5 VDDD（1.8V）
2. **量 pin20 MCLK 是否有 12.288MHz 波形**（这是唯一还没直接观测过的信号。
   `clk_summary` 只说明 SoC 内部 clock 在跑，不代表引脚输出。
   ⚠ 不要再用 `/dev/mem` 或 ioremap 直接读 GPIO 寄存器 —— 已两次把板子读挂，
   需要先 `clk_get_sys`/`of_clk_get` 拿到 `pclk_gpio3` 才行，见 `kernel-modules/gpioprobe/`）
3. **量 pin3 SDOUT 在录音时是否有波形**，以及是否连通到 SoC pin123
4. 量 pin6 SCLK、pin7 LRCK 是否有波形（播放时 ES7148 正常 ⇒ 这条 I2S 时钟网络应该是好的，
   但 ES7148 与 ES7243 是否共用同一对引脚也值得确认）

### 可回退状态
- DTS：`/boot/dtb/rockchip/rk3399-mid.dtb.bak-*`（多份，含 preclk / premic）
- 驱动：`seq_variant=0/1/2/3` 四档，`trcm_txonly`、`auto_bclk_ratio` 均可运行期切换
- `kernel-modules/gpioprobe/` 是诊断模块，不参与正常功能
