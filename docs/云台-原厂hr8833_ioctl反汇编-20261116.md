# RK3399 原厂 HR8833 驱动 ioctl 逆向分析

## 0. 结论速览（可直接落地）

三个 cmd 的实参语义已完全确定 —— **ioctl 只读 `cmd`（第 2 个参数 `x1`），完全不读第 3 个参数 `arg`（`x2`），没有 `copy_from_user`、没有 `get_user`、没有计时器/延时、没有 PWM 操作**。

| cmd | 宏名 | 数值 | 驱动实际动作 | 对 H 桥（AIN1/AIN2）的效果 |
|-----|------|------|--------------|---------------------------|
| `_IOW('m',0x18,int)` | Ioenable | `0x40046d18` | AIN1=0, AIN2=0 | **停止/惰行（coast，两路输出高阻）** ← 名字误导，实际是 stop |
| `_IOW('m',0x19,int)` | Ioforward | `0x40046d19` | AIN1=0, AIN2=1 | 正转 |
| `_IOW('m',0x1a,int)` | Ioreverse | `0x40046d1a` | AIN1=1, AIN2=0 | 反转 |

- **forward/reverse 的实参既不是速度、也不是时长、也不是步数 —— 完全被忽略。** App 传什么值都无所谓；电机以硬件决定的满速运转（本驱动未接 PWM）。方向由 cmd 本身编码。
- **nSLEEP 不在 ioctl 中切换**：probe 里置高一次，`suspend` 置低、`resume` 置高。
- **OCP 检测未实现**：`ocp-det-gpio` 在 probe 中只被 `request` 为输入，全驱动没有任何地方读取它（无中断、无轮询）。

## 1. 逆向方法与地址对照

### 1.1 镜像布局
- `kernel.img` = 8 字节 Rockchip `KRNL` 头 + 裸 ARM64 Image（`ARMd` magic 在文件 0x40，即裸 Image 偏移 0x38）；`text_offset=0x80000`，`image_size=0x12ab000`。
- 地址映射（经 cmd 立即数、字符串锚点、helper 符号三重验证）：

  ```
  文件偏移 F  ->  运行时虚拟地址 R(F) = F + 0xffffff8008000000
  kallsyms 表中函数地址 = R + 0x80000
  即 F = kallsyms_addr - 0xffffff8008080000
  ```

  （kallsyms 函数值比实际运行地址整体高 0x80000，与该 Image 的 text 重定位有关。）

### 1.2 kallsyms 解析结果
- 地址表文件偏移 `0xbc8908`，`num_syms=105989`（@`0xc97a08`），名字表 @`0xc97b08`（前面 `0xc97b00` 有 8 字节填充），`token_table` @`0xde8d08`，`token_index` @`0xde9108`。
- 关键符号（运行时地址 = kallsyms 值 − 0x80000；文件偏移 = kallsyms 值 − 0xffffff8008080000）：

| 符号 | kallsyms vaddr | 运行时 vaddr | 文件偏移 |
|------|----------------|--------------|----------|
| `hr8833_ioctl` | 0xffffff800845758c | 0xffffff80083d758c | **0x3d758c** |
| `hr8833_write` | 0xffffff8008457658 | 0xffffff80083d7658 | 0x3d7658 |
| `hr8833_read` | 0xffffff8008457678 | 0xffffff80083d7678 | 0x3d7678 |
| `hr8833_release` | 0xffffff800845756c | 0xffffff80083d756c | 0x3d756c |
| `hr8833_probe` | 0xffffff80084576f4 | 0xffffff80083d76f4 | 0x3d76f4 |
| `hr8833_suspend` | — | — | 0x3d74fc |
| `hr8833_resume` | — | — | 0x3d7524 |
| `g_hr8833`（全局结构指针） | 0xffffff80092df710 | 0xffffff800925f710 | 0x125f718 |
| `hr8833_driver_fops` | 0xffffff800915f540 | — | ~0x10df548 |

### 1.3 定位方式
用字符串 `hr8833_ioctl. cmd = %d\n`（文件 0xe2ea66）的 ADRP+ADD 引用扫描，再以三条 `mov w0,#0x6d18/0x6d19/0x6d1a; movk w0,#0x4004,lsl#16` 立即数序列为铁证，锁定 ioctl 函数起点在文件 0x3d758c。helper 调用经 kallsyms 反查确认为 `printk` / `gpio_to_desc` / `gpiod_set_raw_value`。

## 2. `hr8833_ioctl` 完整反汇编与逐条解读

函数范围：文件 `0x3d758c`–`0x3d7650`（运行时 `0xffffff80083d758c`）。

```asm
; 函数序言 + 打印调试信息
0x3d758c stp x29,x30,[sp,#-0x20]!
0x3d7590 adrp x0, 0xffffff8008e2e000
0x3d7594 mov x29, sp
0x3d7598 add x0, x0, #0xa5e          ; "hr8833_ioctl. cmd = %d\n"
0x3d75a0 mov w19, w1                 ; w19 = cmd（第2个参数）★ 唯一被读取的入参
0x3d75a4 bl printk

; ---- cmd 分派（比较完整 32 位 cmd 值）----
0x3d75a8 mov  w0, #0x6d19
0x3d75ac movk w0, #0x4004, lsl #16   ; w0 = 0x40046d19 (Ioforward)
0x3d75b0 cmp  w19, w0
0x3d75b4 b.eq 0x3d761c               ; -> forward
0x3d75b8 mov  w0, #0x6d1a
0x3d75bc movk w0, #0x4004, lsl #16   ; w0 = 0x40046d1a (Ioreverse)
0x3d75c0 cmp  w19, w0
0x3d75c4 b.eq 0x3d75f0               ; -> reverse
0x3d75c8 mov  w0, #0x6d18
0x3d75cc movk w0, #0x4004, lsl #16   ; w0 = 0x40046d18 (Ioenable)
0x3d75d0 cmp  w19, w0
0x3d75d4 b.ne 0x3d7648               ; 其它 cmd -> 直接返回

; ---- Ioenable (0x18)：AIN1=0, AIN2=0 ----
0x3d75d8 adrp x19, 0xffffff800925f000
0x3d75dc ldr  x0, [x19,#0x710]       ; x0 = g_hr8833（全局结构指针）
0x3d75e0 ldr  w0, [x0,#8]            ; g->ain1_gpio
0x3d75e4 bl   gpio_to_desc
0x3d75e8 mov  w1, #0
0x3d75ec b    0x3d7604               ; gpiod_set_raw_value(ain1, 0)
0x3d7608 ldr  x0, [x19,#0x710]
0x3d760c ldr  w0, [x0,#0xc]          ; g->ain2_gpio
0x3d7610 bl   gpio_to_desc
0x3d7614 mov  w1, #0
0x3d7618 b    0x3d7644               ; gpiod_set_raw_value(ain2, 0)

; ---- Ioreverse (0x1a)：AIN1=1, AIN2=0 ----
0x3d75f0 adrp x19, 0xffffff800925f000
0x3d75f4 ldr  x0, [x19,#0x710]
0x3d75f8 ldr  w0, [x0,#8]            ; ain1
0x3d75fc bl   gpio_to_desc
0x3d7600 mov  w1, #1
0x3d7604 bl   gpiod_set_raw_value    ; gpiod_set_raw_value(ain1, 1)
0x3d7608 ldr  x0, [x19,#0x710]
0x3d760c ldr  w0, [x0,#0xc]          ; ain2
0x3d7610 bl   gpio_to_desc
0x3d7614 mov  w1, #0
0x3d7644 bl   gpiod_set_raw_value    ; gpiod_set_raw_value(ain2, 0)

; ---- Ioforward (0x19)：AIN1=0, AIN2=1 ----
0x3d761c adrp x19, 0xffffff800925f000
0x3d7620 ldr  x0, [x19,#0x710]
0x3d7624 ldr  w0, [x0,#8]            ; ain1
0x3d7628 bl   gpio_to_desc
0x3d762c mov  w1, #0
0x3d7630 bl   gpiod_set_raw_value    ; gpiod_set_raw_value(ain1, 0)
0x3d7634 ldr  x0, [x19,#0x710]
0x3d7638 ldr  w0, [x0,#0xc]          ; ain2
0x3d763c bl   gpio_to_desc
0x3d7640 mov  w1, #1
0x3d7644 bl   gpiod_set_raw_value    ; gpiod_set_raw_value(ain2, 1)

0x3d7648 ldp x19,x20,[sp,#0x10]      ; 公共返回路径（未显式设置返回值，x0 保持 printk 返回值）
0x3d764c ldp x29,x30,[sp],#0x20
0x3d7650 ret
```

### 关键观察
1. **只比较 `cmd`**：`b.eq` 全在 `w19`（= `x1` = cmd）上做。`x2`(arg)、`x0`(filp) 除取全局指针外**从未被当作数据读取**。
2. **没有 `copy_from_user` / `get_user`**：函数内的 BL 只有 `printk`、`gpio_to_desc`、`gpiod_set_raw_value`（已逐个用 kallsyms 反查确认）。
3. **没有延时/定时器/PWM**：三个分支都是纯 GPIO 写。
4. **`Ioenable` 名不副实**：它把 AIN1/AIN2 都拉低。对 DRV8833/HR8833 这类 H 桥，AIN1=AIN2=0 是**高阻惰行（stop）**（AIN1=AIN2=1 才是刹车）。所以正确时序是：`Ioenable`（初始化/停止）→ `Ioforward`/`Ioreverse`（运转），需要停时再发一次 `Ioenable`。置信度：高（汇编直接可见两路均写 0；H 桥语义为通用常识）。

## 3. 电机 GPIO 控制时序

### 3.1 全局结构与偏移（由 probe 反推）
`g_hr8833` 指向 probe 中 `devm_kmalloc(...,0x40,GFP_KERNEL|__GFP_ZERO)` 的结构：

| 偏移 | 字段 | 来源 DTS 属性 | 初始状态 |
|------|------|--------------|----------|
| 0x00 | `struct device *dev` | — | &pdev->dev |
| 0x08 | `ain1_gpio` (int) | `ain1-gpio` | request 为输出低；`gpiod_set_raw_value(0)` |
| 0x0c | `ain2_gpio` (int) | `ain2-gpio` | request 为输出低；`gpiod_set_raw_value(0)` |
| 0x10 | `sleep_gpio` (int) | `sleep-gpio` | request 为输出；**`gpiod_set_raw_value(1)` → nSLEEP 高，电机上电** |
| 0x14 | `ocp_gpio` (int) | `ocp-det-gpio` | request 为输入（`GPIOF_IN`），label `"ocp_det"` |
| 0x28 | `device *` | device_create | — |
| 0x30 | `class *` | __class_create | — |
| 0x38 | `cdev *` | cdev_alloc | — |

probe 对每个 GPIO 的模式：`of_get_named_gpio_flags()` → `devm_gpio_request_one()` → `gpio_to_desc()` → `gpiod_set_raw_value()`。注意用的是 **raw value**（忽略 DTS 的 `GPIO_ACTIVE_LOW` 标志），所以 `sleep=1` 即物理高电平。

### 3.2 时序
```
上电/probe:
  AIN1=0, AIN2=0, nSLEEP=1(高)      ; 电机上电但惰行
  ocp-det 配为输入

App 控制（ioctl）:
  Ioenable(0x18)   -> AIN1=0, AIN2=0   ; 停止/惰行
  Ioforward(0x19)  -> AIN1=0, AIN2=1   ; 正转（满速）
  Ioreverse(0x1a)  -> AIN1=1, AIN2=0   ; 反转（满速）

系统 suspend (0x3d74fc):  gpiod_set_raw_value(sleep_gpio, 0)  ; nSLEEP 低 -> 休眠
系统 resume  (0x3d7524):  gpiod_set_raw_value(sleep_gpio, 1)  ; nSLEEP 高 -> 唤醒
```
`suspend`/`resume` 反汇编（文件 0x3d74fc / 0x3d7524）：
```asm
; suspend
ldr x0,[x0,#0xb0]        ; pdev->driver_data = g
ldr w0,[x0,#0x10]        ; sleep_gpio
bl  gpio_to_desc
mov w1,#0
bl  gpiod_set_raw_value  ; nSLEEP=0
; resume 同上但 mov w1,#1
```

### 3.3 read/write/open/release
均为桩函数：`printk()` 后返回（`read`/`write` 返回立即数 4），不参与电机控制。`file_operations` 中 `.read/.write` 指向这些桩，`.unlocked_ioctl/.compat_ioctl` 指向 `hr8833_ioctl`（指针值 0xffffff800845758c 出现在 fops 结构中）。

## 4. OCP 检测逻辑

**结论：原厂驱动没有实现 OCP 检测。**

- probe 中：`of_get_named_gpio_flags(...,"ocp-det-gpio",...)` → 存入 `g->ocp_gpio`（偏移 0x14）→ `devm_gpio_request_one(dev, gpio, GPIOF_IN /* w2=1 */, "ocp_det")`。
- 反查 `g_hr8833` 全局的全部引用：**只有 3 处，全部在 ioctl 内**（且都只读偏移 8/0xc，即 AIN1/AIN2）。
- 扫描 driver 代码区 `0x3d7480–0x3d7b20` 内对 `[reg,#0x14]` 的读取：**只有 2 处，都在 probe 的错误打印路径**（`ldr w20,[x19,#0x14]` @0x3d7944、`ldr w2,[x19,#0x14]` @0x3d796c），即 `dev_err("failed to request ocp-det-gpio: %d\n", ...)`。
- 全内核扫描对 `gpiod_get_value` / `gpiod_get_raw_value` 的 BL 调用点：driver 代码区**无任何命中**；probe 中也没有 `request_irq` / `gpio_to_irq` / 定时器。

即 `ocp-det-gpio` 仅被"占住"配置为输入，硬件若拉低 OCP，驱动不会感知也不会停电机。mainline 驱动不必为兼容原厂 App 而实现 OCP 读取逻辑。

## 5. 对 mainline `hr8833.c` 的改造建议

要让原厂 App（magic='m' 的 cmd）直接可用，最小改动如下：

1. **新增三个 cmd 宏**（保留现有 magic='H' 的自定义 cmd 以兼容自有 App）：
   ```c
   #define HR8833_IOC_MAGIC 'm'
   #define HR8833_IOENABLE   _IOW(HR8833_IOC_MAGIC, 0x18, int) /* 0x40046d18 */
   #define HR8833_IOFORWARD  _IOW(HR8833_IOC_MAGIC, 0x19, int) /* 0x40046d19 */
   #define HR8833_IOREVERSE  _IOW(HR8833_IOC_MAGIC, 0x1a, int) /* 0x40046d1a */
   ```
   注意 `_IOW('m',nr,int)` 在 ARM64 上恰好等于 `0x40046d00|nr`，与原厂完全一致。

2. **在 `unlocked_ioctl` 中按完整 cmd 值分派**（不要只取 `_IOC_NR`，避免与自有 cmd 冲突），动作严格对齐：
   - `IOENABLE`：`gpiod_set_value(ain1,0); gpiod_set_value(ain2,0);`
   - `IOFORWARD`：`gpiod_set_value(ain1,0); gpiod_set_value(ain2,1);`
   - `IOREVERSE`：`gpiod_set_value(ain1,1); gpiod_set_value(ain2,0);`
   - 不要从 `arg` 拷贝任何值；返回 0。

3. **nSLEEP 处理**：probe 中初始化为高（注意若用 `gpiod_set_value` 且 DTS 标 `GPIO_ACTIVE_LOW`，要写 1 才会输出物理高；为与原厂 raw 行为一致可用 `gpiod_set_raw_value` 或核对 polarity）。实现 `suspend/resume` 回调拉低/拉高 nSLEEP。

4. **OCP**：无需为 App 兼容实现；若要增强，可另加 input GPIO + 中断，但不影响与原厂 App 的互操作。

5. **保留 debug 打印** `printk("hr8833_ioctl. cmd = %d\n", cmd)` 可帮助验证原厂 App 发出的 cmd。
