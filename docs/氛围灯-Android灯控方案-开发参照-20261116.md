## 0. 一句话结论

原厂灯控是 **两层叠加**：
1. **内核驱动 `sn3732a.ko`**（编译进 kernel.img）—— probe 阶段全亮（开机粉色）+ `sn3732a-leds-wq` workqueue 异步按 红/绿/蓝/黄 **整片轮切**；这是**开机彩虹灯**的来源。
2. **APK 运行时控制**—— `fsmeeting` 的 `GlobalReceiver` 按网络状态经 JNI ioctl 叠加单色；`HwMonkeyTest` 产线 App 有红→绿→蓝 100ms 循环测试。

芯片本身 = **ISSI/Lumissil IS31FL3732A 寄存器兼容**（144-LED 矩阵驱动，8 帧动画，级联），有完整公开手册 ⇒ **mainline 下无需逆向，直接 i2c 写寄存器即可控灯**，已实测成功。

## 1. 硬件层

| 项 | 事实 | 证据 |
|---|---|---|
| 芯片 | **SN3732A（矽恩微 Si-En）×3** = IS31FL3732A 寄存器兼容 | 型号尾缀 3732A + 三片级联 + audio-modulated LED 特征；实测 page 机制/寄存器回环/帧随机值全吻合 |
| 总线/地址 | i2c6 `0x50` / `0x52` / `0x53`（0x51 无器件） | `i2ctransfer` 三片全 ACK |
| enable | **GPIO2_B0 = pin 72**，高有效 | vendor DTS `sn3732a_50@50 { enable-gpio = <&gpio2 8 GPIO_ACTIVE_HIGH>; }`；pinctrl `rockchip,pins = <2 8 0 0xbe>`。mainline sysfs 需 `echo 72 > export; echo out > direction; echo 1 > value` |
| 通道规模 | 每片 9×16 = 144 LED，共 3 片级联 | datasheet；板上只接了其中一部分（全开呈粉色 = R+B 通道有灯，非白光） |
| 设备节点 | 原厂 `/dev/sn3732a`（misc 字符设备）；**mainline 无此节点、无驱动** | 反编译 JNI `open("/dev/sn3732a", O_RDWR)`；mainline `/sys/class/leds/` 只有 mmc1 |

## 2. 寄存器层（IS31FL3732A Rev.D，实测兼容）

### 2.1 Command Register（页选择）—— 写 `FDh`

| 值 | 页 |
|---|---|
| `0x00..0x07` | Frame 1..8 |
| `0x0B` | Function register page |

### 2.2 Function page（`FD=0x0B`）

| 地址 | 名称 | 位定义 |
|---|---|---|
| `00h` | Configuration | D7:D6 SYNC(00=disable,01/10/11=master/slave 级联)、D4:D3 MODE(00=Picture,01=Auto Frame Play,10=Audio Sync)、D2:D0 FS(帧起始号) |
| `01h` | Picture Display | D2:D0 PFS（显示第几帧） |
| `02h` | Auto Play Control 1 | D6:D4 CNS(循环次数,000=infinite)、D2:D0 FNS(播放帧数) |
| `03h` | Auto Play Control 2 | D5:D0 A（帧间隔 = A × 8.8ms） |
| `04h` | Global Current Control | 0..255 全局电流 |
| `05h` | Display Option | D5 IC、D3 BE(blink enable)、D2:D0 BPT(blink period) |
| `08h` | Breath Control 1 | D6:D4 FOT(fade out time)、D2:D0 FIT(fade in time) |
| `09h` | Breath Control 2 | D4 B_EN(呼吸使能)、D2:D0 ET |
| `0Ah` | Shutdown | **`01` = Normal Operation**；`00`/`1x` = SW shutdown |

### 2.3 Frame page（`FD=0x00..0x07`）

| 地址范围 | 名称 | 说明 |
|---|---|---|
| `00h..11h` | LED Control | 18 字节 × 8 bit = 144 颗，bit=1 点亮 |
| `12h..23h` | Blink Control | 18 字节，bit=1 该 LED 参与 blink |
| `24h..B3h` | PWM | 144 字节，每 LED 独立亮度 0..255 |

> 上电 Frame 寄存器值是随机的（手册原文 "Frame Registers are random after power up"）—— 实测吻合，故初始化必须显式写全帧。

### 2.4 最小点亮流程（实测可用）

```
1. FD=0x0B      选 Function page
2. 0A=0x01      Normal operation（退出 shutdown）
3. 00=0x00      Picture mode
4. 01=0x00      显示 Frame1
5. 04=0xFF      GCC 最大电流
6. 05=0x00      无 blink
7. FD=0x00      选 Frame1 page
8. 00h..11h=FF  全 LED 开
9. 12h..23h=00  关 blink
10. 24h..B3h=FF 全 PWM 满
⇒ 灯亮（板上实测粉色常亮）
```

## 3. 内核驱动层（原厂 `sn3732a.ko`，开机灯效来源）

### 3.1 字符串证据（从 kernel.img 4.4.83 提取）

| 字符串 | 含义 |
|---|---|
| `si-en,sn3732a` / `sn3732a_probe` / `sn3732a_remove` | of_platform 驱动，编译进内核 |
| `sn3732a: trun on all leds setting error in probe!` | **probe 阶段就点亮所有灯**（typo "trun" 原样）⇒ 开机上电即亮 |
| `sn3732a: trun off leds setting error while shutdown!` | 关机/charger 状态关灯 |
| `sn3732a-leds-wq` | **workqueue 名** ⇒ 灯效异步跑 |
| `sn3732a_blu(e)` / `_g(reen)` / `_i2(c)` | 单色切换的静态函数（printk `__func__` 碎片） |
| `sn3732a_ioctl/open/read/write/release` | 标准 file_operations，实现 `/dev/sn3732a` |
| `sn3732a_ioctl. cmd = %u` | ioctl 命令分发 |
| `switch to page 5 err` / `page 9 err` | 驱动用多页/多帧（对应 IS31FL3732A 8 帧） |
| `single red/green/blue/yellow leds setting error!` | 四色控制入口 |

### 3.2 开机灯效控制策略（还原）

```
上电 → driver probe → "turn on all leds" → 全亮（粉色，R+B 通道）
     → 启动 sn3732a-leds-wq workqueue
     → 按 红/绿/蓝/黄 整片轮切（非逐颗跑马），肉眼看像彩虹流转
     → 关机/shutdown → "turn off leds"
```

**关键点**：原厂是**整片单色轮切**（整颗芯片所有 LED 一起变一个颜色），不是逐颗 LED 流动。这解释了用户反馈"我的逐 bit 跑马和开机彩虹不同"。

### 3.3 静态逆向边界（已探尽，勿重复）

- kallsyms 32 位名字表回退扫描失败；64 位地址表定位到 `0xffffff8008080000` 起 105989 项，但 `sn3732a_probe` 全局符号地址需解 token 压缩名表，投入产出低。
- 只有 `sn3732a_probe`/`remove` 是全局符号，ioctl/workqueue/单色函数都是 static，不进 kallsyms。
- ⇒ 停止静态反汇编，改用字符串证据 + 动态实测复刻（见 §6）。

## 4. APK 层（运行时叠加控制）

### 4.1 两个定制 APK

底包 83 个 APK 中只有 2 个含 `sn3732a`/`libJniledctl`：
- `priv-app/fsmeeting`（会议主程序，42 MB）
- `priv-app/HwMonkeyTest`（产线硬件测试，包名 `com.rabi.gpiojni`）

反编译：apktool + JDK21（`/Users/wcg/.Trash/WorkBuddy/软件定制/.tools/jdk-21.0.12.1+1/Contents/Home`；本机 `/usr/bin/java` 是 stub），产物 `/tmp/led-apk/smali-{fs,hw}/`。

### 4.2 调用链（fsmeeting 网络状态灯）

```
GlobalReceiver.onConnectivityStateChanged(state)
  state 0x65→LedblueOn / 0x66→LedyellowOn / 0x67→updateLed()
  updateLed(): 按 WiFi 信号等级 → 红(断开/无网/信号0) / 黄(中) / 蓝(强)
  → LedctlHelper (static native)
  → System.loadLibrary("Jniledctl") → libJniledctl.so
  → open("/dev/sn3732a", O_RDWR=2) + ioctl(fd, cmd)
```

### 4.3 ioctl 命令码（反汇编 `libJniledctl.so`，capstone Thumb）

`_IOW('s', nr, int)`，magic=`'s'`=0x73，size=4：

| 函数 | cmd 值 | nr |
|---|---|---|
| LedredOn | `0x4004 7312` | 0x12 |
| LedgreenOn | `0x4004 7313` | 0x13 |
| LedblueOn | `0x4004 7314` | 0x14 |
| LedyellowOn | `0x4004 7315` | 0x15 |
| LedallOn | `0x4004 7316` | 0x16 |
| LedallOff | `0x4004 7317` | 0x17 |

> PLT 映射：0x20ec=ioctl、0x20fc=__android_log_print、0x210c=open、0x211c=close。两个 App 的 so md5 不同（fs=全功能，hw=精简）。
> **APK 只有整片单色/全开全关，无逐 LED 流动/彩虹渐变。**

### 4.4 HwMonkeyTest 产线灯效

`MainActivity2$2.smali`：红→绿→蓝循环，`Thread.sleep(0x64)` = **100ms** 节奏；另有随机延时模式（`access$202`）。`access$000` 控循环开关。**这是同一套整片轮切策略的 App 侧实现**（产线测试用）。

### 4.5 两 APK 的完整 JNI 硬件接口（旁证，勿混淆）

| JNI 库 | native 方法 | 硬件 |
|---|---|---|
| libJniledctl.so | LedOpen/Close/allOn/allOff/red/green/blue/yellowOn | 氛围灯 SN3732A |
| libJniioctl.so | Ioenable/Ioforward/Ioreverse/init/destroy | 云台电机（`AudioCaptureDetectHelper` 声源定位转向） |
| libJnitest.so | init/setTime/writeTime | RTC |

## 5. 电源灯 / 按键灯（灯控方案相关结论）

- **无独立 GPIO LED**：原厂 `lights.rk3399.so` 只操作 backlight，不碰 GPIO LED；vendor DTS 全板无 `gpio-leds` 节点；mainline `/sys/class/leds/` 只有 `mmc1::`。
- **电源按键 LED**：用户实测上电即亮，但 APK/HAL/DTS 均无软件控制证据 ⇒ **硬件直驱（PMIC/常亮），非软件外设，无需驱动**。
- 橙/绿充电指示疑由氛围灯 SN3732A 兼任（JNI 四色可映射），或背光体现。

## 6. mainline 复刻：脚本与测试

### 6.1 测试脚本

- 板上：`/root/sn3732a.py`；本地永久源：`docs/sn3732a-灯控测试脚本.py`（md5 `6cf3040f9a7973db549d1bbdd9288b1d`，临时工作副本在 `/tmp/led-apk/sn3732a.py`）。
- 封装 i2ctransfer 的 page/寄存器读写，命令：

| 命令 | 功能 |
|---|---|
| `init` | 三片初始化为 Picture mode / Normal op |
| `solid [color]` | 全通道常亮（板上呈粉色） |
| `chase [sec]` | 逐 bit 跑马（144 通道；因板上未接满通道会断） |
| `breathe [sec]` | 呼吸（软件扫 GCC 0↔255） |
| `demo` | 3 轮：常亮2s→跑马4s→呼吸4s |
| `workqueue [rounds]` | **★ 复刻原厂 workqueue 异步灯效**（见下） |
| `calib` | 18 组 LED-control byte 逐个点亮，用于标定颜色/位置映射 |
| `off` | 全灭（SW shutdown） |

> enable GPIO72 需先手动拉高：`echo 72 > /sys/class/gpio/export; echo out > /sys/class/gpio/gpio72/direction; echo 1 > /sys/class/gpio/gpio72/value`。

### 6.2 ★ workqueue 异步灯效复刻（本次实测）

`workqueue_effect()` 忠实还原原厂驱动的三阶段策略，并用**后台线程跑灯效 + 主线程持续心跳**证明"异步"：

```
probe 阶段：   全亮，保持 1s（=开机粉色）
workqueue 阶段：后台线程按 [ALL / GRP-A / GRP-B / GRP-C / GRP-ALT] 整片轮切，每组 0.45s
               （5 个 pattern 分别代表 probe 全亮 + 红/绿/蓝/黄 的替身）
shutdown 阶段：全灭
```

执行：`python3 -u /root/sn3732a.py workqueue 3`

**3 轮实测结果（2026-11-16 17:xx）**：
- 输出中 `[main] heartbeat` 与 `[WQ] round` 交替出现 ⇒ 灯效确实在后台线程异步跑，主线程未被阻塞。
- 3 轮各阶段 pattern 正常轮切，`[WQ][shutdown] all LEDs OFF` 收尾。
- **颜色映射待用户反馈**：各 GRP 具体呈什么颜色/位置未确认（板上未接满 144 通道，pattern 与物理 LED 接法决定颜色）。

### 6.3 待办：精确复刻开机彩虹

1. 用 `calib` 标定 18 组中哪几组实际接灯、分别红/绿/蓝/黄哪一色。
2. 将 `workqueue_effect` 的 5 个 pattern 替换为真实颜色对应的通道组。
3. （可选）用 IS31FL3732A 硬件 Auto Frame Play（MODE=01，8 帧预存 + Breath）替代软件线程，进一步贴近原厂（原厂驱动 `switch to page 5/9` 暗示用了多帧）。

## 7. 正式驱动开发参照（若后续写 `leds-sn3732a.c`）

- **路线**：mainline 已有 `leds-is31fl32xx` 驱动家族（含 is31fl3216/3218/3731），但**不含 3732**。SN3732A 寄存器兼容 IS31FL3732A，可基于 `leds-is31fl32xx.c` 扩展一个 3732 变体（144 LED / 18 LED-control 字节 / 8 帧）。
- **或者**：更轻量地写一个专用字符设备 `/dev/sn3732a` 复刻原厂 ioctl（cmd 0x12..0x17），让原厂 APK 逻辑可直接跑——这是"原厂行为兼容"路线。
- **DTS 节点参照**：
  ```
  sn3732a: led-controller@50 {
      compatible = "si-en,sn3732a";   // 或 "issi,is31fl3732"
      reg = <0x50>;
      enable-gpios = <&gpio2 8 GPIO_ACTIVE_HIGH>;
      // 三片级联：0x50/0x52/0x53，SYNC 位配 master/slave
  };
  ```
- **注意**：三片级联的 SYNC 配置（Configuration D7:D6）决定动画同步，复刻开机整片轮切时需三片同步设置，否则会错位。
