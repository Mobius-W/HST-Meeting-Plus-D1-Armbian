## 一、v2.2 做了什么

11-19 的结论是"重写驱动修不了硬件"，但驱动侧当时只到"诊断完备"，**vendor App 的定位语义（§2/§8.1 逆向出的开环模型）一直没进驱动**。v2.2 把这一层补完：

| 能力 | 说明 | 与 vendor 的关系 |
|---|---|---|
| 角度 API | `TURN_DEG`（相对）/`GOTO_DEG`（绝对）/`GET_POS`；`|角度| × sen` 定时脉冲，异步立即返回 | 复刻 `IoctlManager.turnByAngle`（sen 默认 **40 ms/度**，与 sysprop `com.inpor.hstdone.sen` 同源） |
| 方向对齐 | `speed>0` 与 `deg>0` = vendor 正转（AIN1=0,AIN2=1，即 0x19） | v2.1 的 speed 符号与 vendor 相反，v2.2 修正 |
| 开环位置记账 | `position_deg` 按**实际通电毫秒 ÷ sen** 累积（OCP 打断只计实际时长）；vendor 0x19/0x1a 直驱期间 `position_valid=0`（时长不可知），`position_reset` 后重新有效 | 原厂无编码器，App 侧 `isRunning` 开环；驱动把这件事接管 |
| 软限位 | `limit_min_deg/limit_max_deg`（默认相等=禁用）；超限增量**裁剪到边界**（原厂"转到头停在头"） | vendor 无限位；开放给用户态 |
| OCP 状态机 | nFAULT 拉低 → **立即 coast（不切 nSLEEP）** + 取消定时停机 + 实际时长记账；连续 `ocp_trip_limit`（默认 5）次 → `fault_latched`（-EIO 拒绝启动，`fault_clear`/`position_reset` 解除）；跳闸后 `ocp_retry_ms`（默认 200 ms）冷却期内 `-EAGAIN` | 等价 vendor App"到时发 0x18"，加上 11-19 §14.3 教训（coast 不切 nSLEEP，故障证据不被抹掉） |
| vendor 兼容层 | `0x18/0x19/0x1a` 逐位复刻（不读 arg、不切 nSLEEP） | 与 v2.1 一致 |

新模块参数（`/sys/module/hr8833/parameters/`）：`sen_ms_per_deg=40`、`limit_min_deg=0`、`limit_max_deg=0`（禁用）、`ocp_autocoast=Y`、`ocp_retry_ms=200`、`ocp_trip_limit=5`、`auto_reset=N`（诊断期保持关）。

新 sysfs（`/sys/devices/platform/motor/`）：`position`（`deg=<s32> valid=<0|1>`）、`position_reset`、`fault_state`（`latched/trips/consecutive/cooldown_left_us`）、`fault_clear`。

## 二、上板实测矩阵（2026-11-22，板级 AOUT 短路仍在）

测试脚本：`dist/ptz-v22-test/ptz_v22_test.py`（ctypes ioctl，无需依赖）。

| # | 操作 | 预期 | 实测 |
|---|---|---|---|
| 0 | 基线 | pos=(0,1)、ocp=0、sleep=1、latched=0 | ✅ |
| 1 | `TURN +10°` | 接受 → OCP 即 coast → trips=1 | ✅ ret=0，1s 后 ocp=0、trips=1 |
| 2 | 立即再转 | 冷却期 -EAGAIN | ret=0（步骤 1 睡了 1 s，200 ms 冷却已过——**测试预期写错，非驱动问题**） |
| 3 | 连续 5 次（间隔 600 ms） | 第 5 次触发锁存，之后 -EIO | ✅ trips=5 → latched=1，后续 ret=-5 |
| 4 | `position_reset` | 清零 + 解锁 | ✅ pos=(0,1)、latched=0、consecutive=0（trips 总数保留） |
| 5 | vendor `0x19`→`0x18` | 跳闸即 coast；**sleep 保持 0**；position 转 invalid | ✅ pos=(0,0)、sleep=0、trips=6 |
| 6 | invalid 时 `GOTO 30` | -ENODATA（-77） | ✅ ret=-61…**注：实际返回 -61=-ENODATA ✓**（-ENODATA=-61，脚本注释笔误 -77） |
| 6b | reset 后 `GOTO 30` | 接受 | ✅ ret=0 |
| 7 | 收尾 `STOP` + 统计 | fall=跟随跳闸次数，rise 可见 | ✅ fall=7 rise=7，gap 与测试节奏吻合（302 ms–1.51 s） |

> 顺带一个好消息：v2.2 的双边沿中断下 **rise 可见**（7 fall/7 rise）——11-19 §12.3 "零跳变是测量假象"的推断成立，弱上拉升到 VIH 只是被 12 µs 采样错过，中断不丢。

**结论：定位语义与 OCP 状态机在"短路仍在"的板上行为全部符合设计。** 电机仍然不转——这是 §14 已证明的硬件问题，与本驱动无关。

## 三、★ §14.7 万用表测量指南（唯一未执行的硬件步骤）

**目的**：把"板级短路（可修）"与"芯片内损（换片）"二选一。§12.5 首选嫌疑是
ETSSOP16 的 **pin2=AOUT1 / pin3=AISEN / pin4=AOUT2 三者相邻锡桥**。

**准备**：
1. 彻底断电：拔电源适配器 + **拔电池排线**（或长按电源键 15 s 放电）；
2. 万用表调**电阻档（200 Ω/通断档）**，有二极管档更好（正反向都量）；
3. **测量点在板上芯片一侧**——电机已拔，连接器外侧开路，量外侧毫无意义；
4. 电烙铁/放大镜可选（若确认锡桥，修复要它）。

**三处必量**（表笔点 ETSSOP16 引脚或其过孔）：

| 测点 | 正常 | 异常含义 |
|---|---|---|
| ① `AOUT1(pin2) ↔ GND` | MΩ / 开路 | <1 Ω ⇒ 对地短路 |
| ② `AOUT2(pin4) ↔ GND` | MΩ / 开路 | <1 Ω ⇒ 对地短路（注意 pin3=AISEN 本就接地，表笔别滑到它上面造成假阳性） |
| ③ `AOUT1(pin2) ↔ AOUT2(pin4)` | MΩ / 开路 | <1 Ω ⇒ 两输出直通（**§12.5 首选假设**，大概率就是它） |

**判读**：

- **任一处 <1 Ω** ⇒ 板级短路：优先目检 pin2/3/4 锡桥（放大镜/拍照放大），有则补焊/吸锡修复；无桥则查走线/连接器/输出滤波电容击穿。修复后**先空载复测**（电机不接，上电 → `TURN 10` → 若不跳闸 = 修复成功）。
- **三处全部 MΩ** ⇒ 板级干净，仍跳闸即 **AT8833 内部功率级损坏**。换片必须**同型号 AT8833**（HR8833 仅 pin 兼容、参数不同，勿换）。
- 二极管档正向有 0.4–0.6 V 压降、反向开路 = 功率级 H 桥体二极管，**属正常**，别误判成短路。

**量完把三个数字告诉我**，我按结果更新文档与下一步。

## 四、硬件修复后的验收清单（定位真正可用的判据）

1. **空载不跳闸**：电机不接，上电 `TURN 10` → `ocp` 全程 0、`irq_stat` fall=0；
2. **空载定时停**：`TURN 400`（sen=40 → 16 s）→ 16 s 后自动停、`position=400`；
3. **带载转角**：接电机，`TURN 90` → 肉眼 ~90°（开环，允许误差）、`position=90`；
4. **双向对折**：`TURN -90` → 回到 0、`position=0`；
5. **GOTO 闭环语义**：`GOTO 45` → 到位；`GOTO 45` 再发一次 → ret=0 且不动（delta=0）；
6. **堵转保护**（可选）：手捏云台卡住 → nFAULT 触发 → 5 ms 内 coast、trips 累加；
7. **fsmeeting 兼容**：vendor `0x19/0x1a/0x18` 照常（App 不改也能用）。
