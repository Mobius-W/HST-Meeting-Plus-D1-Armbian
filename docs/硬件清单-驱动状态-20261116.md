**③ 归零的错误认知：`MDIV` 不是 MCLK 分频**

一度怀疑 `CKR=0x00033f3f` 里 `MDIV=4` 把 MCLK 压成 3.072 MHz，导致 ES7148 采样率判错。核对 `rockchip_i2s.c:hw_params` 后排除：

```c
mclk_rate = clk_get_rate(i2s->mclk);          /* 12.288M */
bclk_rate = i2s->bclk_ratio * params_rate;    /* 64 × 48k = 3.072M */
div_bclk  = DIV_ROUND_CLOSEST(mclk_rate, bclk_rate);   /* 4  → 写入 MDIV */
div_lrck  = bclk_rate / params_rate;                   /* 64 → 写入 TSD/RSD */
```

**MDIV 是 MCLK→BCLK 的分频，MCLK 引脚上输出的就是 `clk_i2s0` 本身（12.288 MHz）。** 三个数字反推完全自洽，时钟无问题。另：运行中直接写 `I2S_CKR` 无效（寄存器被驱动锁定），不要指望 `/dev/mem` 改这个寄存器做实验。

**⑤ 剩下的唯一嫌疑：模拟侧供电**

ES7148 引脚定义（QFN-12-EP，2.5×2.5 mm，datasheet **Rev 11.0 / 2024-12**）：

```
1 SCLK   2 LRCK   3 CLKIN  4 CAP1   5 CAP2   6 AOUTLN
7 NC     8 GND    9 VDD   10 AOUTRN 11 NC   12 SDATA   13 EP(PGND)
```

| 测点 | 期望值 | 判据 |
|---|---|---|
| **Pin 9 VDD** 对 GND | **3.0–3.6 V** | 为 0 ⇒ 供电没到，追 0Ω 电阻 / load switch |
| Pin 4 / Pin 5（CAP1/CAP2，各接 1 µF 到地） | datasheet 未给标称值 | 属参考滤波脚；只有在 VDD 正常而这里恒 0 V 时才可疑 |
| Pin 6 / Pin 10（AOUTLN/AOUTRN） | 约 **VDD/2 ≈ 1.5 V** 直流偏置 | 有偏置但无交流 ⇒ 数字侧没进来；0 V ⇒ 芯片仍在 power down。**注：470 Ω 串阻两端直流同电位（无直流电流），所以量电阻任一端等价于量引脚** |
| Pin 3 CLKIN（播放中，直流档） | 约 **1.5–1.7 V**（12.288 MHz 方波均值） | 为 0 或恒定 3.3 V ⇒ MCLK 实际没到引脚 |

**优先测 Pin 9 的 VDD**：QFN 引脚 0.4–0.5 mm 间距不好点，**而且表笔很容易同时碰到相邻两脚造成短路**，所以不要点芯片引脚，改点旁边的无源件（一端对地就是对应网络）。

**★ datasheet 关键条款（Rev 11.0）—— 解释了「一点声音都没有」**

> "Upon applying VDD, the device will reset itself and enter **power down state**. During this state, the device **clamps outputs to ground** and powers down the device operation except for clock management unit. Once **proper CLKIN and LRCK clocks are applied**, the device will leave power down state, and the device outputs ramp from ground to common mode voltage softly."

⇒ 上电后芯片**默认在掉电态、模拟输出被钉在 0 V**；必须 **CLKIN（MCLK）与 LRCK 同时有效**才唤醒。这正好对上实测现象：`PCM RUNNING`、MCLK/BCLK/LRCK 全部正常，但**连底噪和开机噗声都没有** —— 不是"信号弱"，是**输出被钳在地**。

⇒ CLKIN/LRCK 比值必须是 Table 1 的合法值（single speed：128 / 256 / 384 / 512 / 640 / 768 / 1024 / 1152 / 1280 / 1536）。实测 48 k → 12.288 MHz = **256**、44.1 k → 11.2896 MHz = **256**，比值合法。

⇒ 判据因此收敛成**二选一**：

| AOUT 直流电平 | 含义 | 下一步 |
|---|---|---|
| **≈ 1.5 V 共模** | DAC **已唤醒**，数字侧进来了 | 问题在 HT4832 / Class-D 那一级，往下游查 |
| **0 V** | DAC **仍被钳在 power down** | 缺 CLKIN 或 VDD，回到上面四个测点 |

**★ 测点实拍定位**（`docs/开发资料/芯片手册/ES7148-元件辨认-20261116.jpg`，底图 = 用户 2026-11-16 实拍；**元件类型经 2026-11-16 二次放大核对，修正了先前误记**）

| 区域 | 元件类型（按本体颜色判定，不看丝印） | 作用 / 测法 |
|---|---|---|
| **①** | **米色/浅褐本体 + 银白端头 = 陶瓷电容 MLCC** | VDD 去耦与 AOUT 滤波（2200 pF / 3.3 µF / 1 µF 都归这一类）。去耦那颗一端对地应 **3.0–3.6 V** |
| **②** | **深黑褐本体 + 银白端头 = 贴片电阻**（⚠️ 早前误标为"470 Ω + 2200 pF"，实际这一框里**没有电容**） | I2S 串阻 或 AOUT 的 470 Ω，见下方"② 那三颗电阻怎么用" |

**★ ② 那三颗电阻怎么用（不点 QFN 引脚、不拆件，也能同时判定"时钟到没到"和"芯片醒没醒"）**

datasheet 里 AOUT 必串 **470 Ω**；I2S 四条线常被串 **22–100 Ω** 抗辐射。两者外观一模一样，只能靠测量区分：

| 步骤 | 操作 | 判读 |
|---|---|---|
| 1 | **断电**，万用表电阻档逐颗量 ② 里三颗 | **≈470 Ω 的那颗 = AOUT 串联电阻**（两端都是 AOUT 节点）；≈0/22/33/47 Ω = I2S 串阻 |
| 2 | 上电，**停止播放**，直流档量每颗两端 | 全部 0 V 或恒 3.3 V（静止态） |
| 3 | **播放音乐**，再量一次 | 某颗从 0 V 跳到 **≈1.6 V** ⇒ 那是 LRCK/SCLK（50 % 方波均值），**证明时钟真的送到芯片**；某颗稳定在 **≈1.5 V 且不随播放变** ⇒ 那是 AOUT，**芯片已退出 power down**；仍 0 V ⇒ 该线无信号 |

**★ 参照设计（2026-11-16 补充检索）**

没有找到某款量产板的完整原理图公开，但 ES7148 外围极简，全球所有板子都是 datasheet 同一套拓扑，区别只在 RC 数值：

> ⚠️ **另注（驱动方向）**：Linux 官方 binding `everest,es7134 / es7144 / es7154` 写的是 **ADC（模拟→数字）**，而 ES7148 是 **DAC（数字→模拟）**。板上现用 `es7134-hifi`，方向是反的；但它无寄存器、DAI 只作占位，`aplay -l` 仍能列出 PLAYBACK 且 PCM 能 RUNNING ⇒ **驱动不是当前瓶颈，不必改**。

> **★ 判伪记录（2026-11-16）**：旧版本写「SN3732A 是模拟输入 Class-D 功放」——**错**。SN3732A 是 Si-En 的 LED 驱动芯片，同族 SN3728「带有音频调制的 LED 矩阵驱动」/ SN3730「带有音频调制模式的 LED 矩阵驱动」/ SN3731「144 颗 LED 矩阵驱动」；"audio modulated" 是**灯效跟音乐呼吸**的功能，被误读成音频功放。原本三条"证据"没有一条成立：
> 1. ~~「SN3732A 节点无 I2S 引用 ⇒ 是模拟输入功放」~~ —— LED 驱动当然不需要 I2S；
> 2. ~~「三颗并联 = L/R/低音」~~ —— 同族 SN3730 规格原话「I2C 接口，地址可选，**支持同时挂四颗**」，0x50/0x52/0x53 正是**多颗级联的地址分配**，与声道无关；
> 3. ~~「`/dev/sn3732a` misc 选 index ⇒ 功放」~~ —— 呼吸灯恰恰需要用户态 ioctl 控灯效；且该条与 `dmesg: addr=0x50 index=1` 一样**在当前工作区没有任何原始存档可复现**，只写在旧笔记里，按不可采信处理。
>
> 真正的功放**没有 DTS 节点**：它不需要寄存器控制，`spk-con-gpio`/`amp-en-gpio` 直接挂在 vendor 魔改的 `es8316@11` 节点上，靠两个 GPIO 使能。这与实测「手动通断 amp-en 6 次喇叭有『啪』声」完全自洽 —— 功放存在且受 amp-en 控制，只是身份不是 SN3732A。
>
> ⇒ **对 SN3732A 的判伪依然成立**（它是灯控，与音频无关）。但当时顺带写下的「ES8316 仍是必经环节，PVDD/CPVDD 测量这条主线不变」**已作废** —— ES8316 根本不存在，真正的 DAC 是 ES7148。

**★ 第二条判伪记录（同日，用户实拍丝印后）**：此前把「0x11 无 ACK」解释成 ES8316 供电没到，是**在错误前提下做的正确推理**。真实情况：

| 旧判断 | 真相 |
|---|---|
| 板上有 ES8316（QFN-32） | **没有**。实物是 **ES7148**（QFN-12 DAC）+ **HT4832**（QFN-16 耳机功放） |
| 0x11 不 ACK ⇒ 四路供电没到 | ES7148 **没有 I2C 接口**，从物理上就不可能 ACK |
| vendor DTS 的 `es8316@11` 是真 codec | 是**空壳节点**：只提供 `#sound-dai-cells`（stub DAI）+ 两个自定义 GPIO 属性 `spk-con-gpio`/`amp-en-gpio`，vendor 驱动不读寄存器 |
| 210 条 `ASoC error(-6)` ⇒ 芯片在但通信失败 | mainline 真 `es8316.c` 在跟**不存在的芯片**通信，错误是必然的 |
| 需要量 PVDD/CPVDD 找到断点 | **伪命题**，没有这颗芯片，也没有这四路供电可量 |

教训：**当"芯片存在"这个前提本身没被实物确认时，任何从 datasheet 推导出来的供电假设都是空中楼阁。** 这一轮排查（总线/MCLK/引脚复用/regulator/gpio 逐个拉高）花的力气全部没有意义 —— 只差一张芯片丝印照片。

**结论**：整条音频链目前**只能出 HDMI 声音**。但阻塞点已经从"找不存在的 ES8316 供电"变成**一件明确的软件工作：把 DTS 的 fake codec 换成 ES7148 的 dummy DAC + SoC 主时钟 + 功放 EN**。没有任何需要万用表的硬件疑点了。

### 2. 「有节点但没驱动」的全量核对

用 `platform 设备有 compatible 却无 driver 符号链接` 反查，结果**只有 28 个 `syscon`/`qos` 节点（syscon 本来就不需要驱动绑定）+ `regulator-vcc5v0-typec0`**。

⇒ **除了已知的 typec0 注册失败，设备树里没有任何一个外设是「有节点却没驱动」的**。这一条同时证明：
- 现网 DTS 的外设声明是完整的；
- 之前判定「无驱动」的 ES7243 / SN3732A / HR8833 / 传感器，**不是漏配了节点，而是真的没有 mainline 驱动或硬件未实装**。

### 3. SD 卡槽：软件层本来就无法证明存在

vendor DTS 给 `dwmmc@fe320000` 配的是 `supports-sd` + `cap-sd-highspeed` + 缺 `non-removable`（像可插拔），
但同时**缺 `cd-gpios`、缺 `broken-cd`**——正常可插拔卡槽必须有卡检测机制，两个都没有。
加上 `vcc_sd` `num_users=0`、`fstab` 无 sdcard 条目、Android 内核日志无任何 `mmc0` 活动。

⇒ 软件层只能证明「**按 SD 卡设计**」，证明不了 PCB 焊了卡座。**与你的实物确认完全一致：没有卡槽。**

### 3c. ★★ 反编译两个定制 APK：灯是 APK 控制（非驱动自主），并挖出全部硬件调用（2026-11-16）

**★ 结论 1：灯确实是 APK 控制，不是内核驱动自主行为。** 调用链完整闭合：
```

  → onConnectivityStateChanged(state): state 0x65→LedblueOn / 0x66→LedyellowOn / 0x67→updateLed()
```

反汇编 `libJniledctl.so`（capstone Thumb 模式）：`LedOpen` 调 `open(path,2)`，`LedallOn/LedredOn/...` 各调一次 ioctl（PLT 0x20ec = ioctl，0x20fc = `__android_log_print`，0x210c = open，0x211c = close，经 `.rel.plt` 映射确认），日志串 `ret %d LedallOn` 等。**两 App 的 so 不同**：fsmeeting 版 md5 `d9408c...` 导出全部 8 函数；HwMonkeyTest 版 md5 `062e32...` 是精简版。

| **libJniledctl.so** | `LedOpen/LedClose/LedallOn/LedallOff/LedredOn/LedgreenOn/LedblueOn/LedyellowOn` | **氛围灯四色** | SN3732A ×3 @ i2c6 0x50/52/53，`/dev/sn3732a` ioctl |

### 3d. ★★★ 氛围灯寄存器兼容破案 + 手动测试成功（2026-11-16 17:00-17:20）

**状态翻转**：§3b/§3c 曾判「寄存器语义无手册、需自写驱动、优先级低」——本节**推翻**：SN3732A 就是 **ISSI/Lumissil IS31FL3732A 的寄存器兼容芯片**（同为 144-LED 矩阵驱动、page 机制、8 帧动画、级联同步），有完整公开 datasheet。**mainline 下无需写驱动，直接 i2c 写寄存器即可控灯，用户实测成功。**

**破案链**：
1. 疑点：三颗 0x50/52/53 级联 + 型号尾缀 3732A + "audio-modulated LED" —— 与 IS31FL3732A 特征完全吻合（该芯片 datasheet 明确支持 audio-syncブレath/级联/8 帧）。
2. **实测验证兼容**（板上 i2c6）：
   - 写 `0xFD=0x0B`（IS31FL3732A 的 Function page 命令）→ 读 0x00–0x0C 全变 `0x00`（该页上电默认值），证明 **Command Register 分页机制一致**；
   - Function 寄存器 `0Ah`(Shutdown) 写 `0x01` 读回 `0x01`、`04h`(GCC) 写 `0xFF` 读回 `0xFF` —— 写回环正确；
   - Frame page (`0xFD=0x00`) 读 LED-control 区为随机值（手册原话 "Frame Registers are random after power up"）—— 完全吻合。
3. **写全亮配置后用户肉眼确认灯亮（粉色常亮）** → 兼容 assumption 被硬件证实。

**关键寄存器表（IS31FL3732A datasheet, Rev.D）**：
- Command Register `FDh`：`0x00..0x07`=Frame1..8 page；`0x0B`=Function page。
- Function page：`00h` Config(D4:D3 MODE: 00=Picture/01=Auto-play/10=Audio, D7:D6 SYNC, D2:D0 FS)、`01h` Picture-Display(D2:D0 PFS 选帧)、`02h` AutoPlay1(D6:D4 CNS 循环数/D2:D0 FNS 帧数)、`03h` AutoPlay2(D5:D0 帧延时 A×8.8ms)、`04h` GCC(0..255 全局电流)、`05h` Display(D3 BE闪烁/D2:D0 BPT)、`08h` Breath1(D6:D4 FOT/D2:D0 FIT)、`09h` Breath2(D4 B_EN 呼吸使能)、`0Ah` Shutdown(**01=Normal**, 00/1x=shutdown)。
- Frame page：`00h..11h` LED-control(每 bit 1 颗 LED, 1=on)、`12h..23h` Blink、`24h..B3h` PWM(每 LED 一字节, 144 字节)。

### L.1 根因：DTS 一个 clock cell（0x56 → 0x59）

| 项 | 修复前 | 修复后 |
|---|---|---|
| `mic-array clocks` | `<&cru SCLK_I2S0_8CH>` = **0x56**（I2S 控制器内部时钟，**不输出到引脚**） | `<&cru SCLK_I2S_8CH_OUT>` = **0x59**（唯一输出到 GPIO4_A0 的引脚级 MCLK） |
| `clk_i2sout` | prep=0 / en=0 / state=**N** | prep=1 / en=1 / **Y**，12.288 MHz，consumer=mic-array |
| ES7148 pin3 CLKIN / 两颗 ES7243 pin20 | 无 MCLK → ES7148 停 power-down（输出钳地）；ES7243 I²C 无应答 | MCLK 与 LRCK 同时到位 → DAC 唤醒出声、ADC 应答 |

**因果链**：DTS 选错时钟 → `clk_i2sout` 从未 enable → GPIO4_A0 无 MCLK → 两个音频芯片都没时钟 → 播放无声 + 录音 `i2c write failed(-6)`。**一个字节同时解释两个症状**。突破口来自 ES7243 ProductBrief / ES7148 DS 两手册里"MCLK/I2C 先决条件"条款。
