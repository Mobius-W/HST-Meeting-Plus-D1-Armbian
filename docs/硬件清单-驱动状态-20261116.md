## E. 音频（本板最大缺口）

| 器件 | 型号 / 参数 | 状态 | 实测证据 |
|---|---|---|---|
| Codec | ES8316 @ i2c1 0x11 | 🟡 | 驱动已绑，声卡注册成功、PCM 可 `RUNNING`，但 **0x11 无 ACK、dmesg 210 条 `ASoC error (-6)`**。**★ datasheet 纠正**：Pin31 `CE` 不是使能脚而是 **I2C 地址选择**（CE=0→0x10，CE=1→0x11），芯片无独立 enable，上电即应响应 ⇒ 不响应只能是**供电没到**。已排除总线/MCLK/引脚复用/regulator（见下） |
| 麦阵 ADC | **ES7243 ×2** @ i2c1 **0x10 / 0x12** | ❌ | 两片均能读寄存器（`0x10` 与 `0x12` 逐字节相同：`0xFD=0xA0`、`0xFE=0x40`，**确认 0x10 是纯 ES7243**），但 **mainline 无驱动**、vendor 也没接进声卡 ⇒ 4 麦完全用不上 |
| ~~功放~~ → **LED 控制器** | **SN3732A ×3** @ i2c6 **0x50 / 0x52 / 0x53** | 🟡 | **★ 2026-11-16 判伪：SN3732A 不是音频功放，是 Si-En「趣味灯 / 矩阵 LED」驱动**（同族 SN3726/3728/3730/3731 全部是 LED 驱动，"audio modulated" 指的是**灯随音乐呼吸**，不是功放）。三片全部 ACK（`50/52/53`），`0x50` 的 `enable-gpio = GPIO2_B0` 读到高 ⇒ **灯控侧是活的**。缺 mainline 驱动（`si-en,sn3216/sn3218` 有 `leds-is31fl32xx` 支持，sn3732a 没有） |
| 耳机检测 | vendor `rockchip_headset`（ADC ch2 + GPIO4_D4 / GPIO4_D6） | ❌ | mainline 无此驱动 |
| 扬声器使能 | `spk-con` = GPIO4_D1 | ✅ | **2026-11-16 修好**：原先被 mainline `vcc5v0_host` 误占（Sapphire 参考设计的脚），已把该 regulator 移到 GPIO2_B4，并给 spk-con 加 gpio-hog 常开。实测 `gpio-25(spk-con) out hi` |
| 功放使能 | `amp-en` = GPIO4_A5 | ✅ | 加 gpio-hog 常开，实测 `gpio-5(amp-en) out hi`。此前手动通断 6 次喇叭有「啪」声 ⇒ 功放上电通路好 |
| I2S0 8ch | `ff880000` | ✅ | 控制器工作；但 codec 不通 ⇒ 采集 rms=73、前 16 字节全 `ff`，无有效数据 |
| HDMI 音频 | `hdmi-sound` | ✅ | card1，PCM 可开 |

**音频已排除项（2026-11-16 完整证据链）**

| 项目 | 结论 |
|---|---|
| I2C 总线 i2c1(ff110000) | 正常 —— ES7243 在 0x10/0x12 应答 |
| MCLK | 正常 —— `clk_i2sout` 跑在 **11.2896 MHz**，consumer = `1-0011`（ES8316 驱动） |
| 引脚复用 | 正常 —— `i2s0_8ch_bus` 第 9 项就是 `<4 RK_PA0 1>` = I2S0_MCLK，且 `i2s@ff880000` 已挂 `pinctrl-0` |
| 声卡 | 正常 —— `rockchipes8316c` 注册成功，PCM 可 `RUNNING` |
| codec regulator | 正常 —— LDO5=3.0 V / LDO7=1.8 V 均 enabled、`num_users=1` |
| gpio4 控制脚 | 逐个拉高 pin16–30 全部无效；vendor 中 gpio4 引用只有 spk-con/amp-en/touch-reset/host1/headset/hp_con/modem-power，**无 CE 控制** |

**⇒ ES8316 需要的四路供电**（QFN-32）：Pin3 **DVDD**、Pin4 **PVDD（数字 IO，I2C 靠它）**、Pin14 **CPVDD**、Pin22 **AVDD**。目前只有 LDO5/LDO7 被驱动接管，**PVDD / CPVDD 是否真到芯片尚未验证** —— 这是下一步唯一要测的东西。

**音频架构（vendor 还原 · 2026-11-16 修正）**：`I2S0 → ES8316(HPOL/HPOR) → 板载模拟输入 Class-D（无 I2C、型号未识别，受 spk-con + amp-en 两脚控制）→ 喇叭`。

> **★ 判伪记录（2026-11-16）**：旧版本写「SN3732A 是模拟输入 Class-D 功放」——**错**。SN3732A 是 Si-En 的 LED 驱动芯片，同族 SN3728「带有音频调制的 LED 矩阵驱动」/ SN3730「带有音频调制模式的 LED 矩阵驱动」/ SN3731「144 颗 LED 矩阵驱动」；"audio modulated" 是**灯效跟音乐呼吸**的功能，被误读成音频功放。原本三条"证据"没有一条成立：
> 1. ~~「SN3732A 节点无 I2S 引用 ⇒ 是模拟输入功放」~~ —— LED 驱动当然不需要 I2S；
> 2. ~~「三颗并联 = L/R/低音」~~ —— 同族 SN3730 规格原话「I2C 接口，地址可选，**支持同时挂四颗**」，0x50/0x52/0x53 正是**多颗级联的地址分配**，与声道无关；
> 3. ~~「`/dev/sn3732a` misc 选 index ⇒ 功放」~~ —— 呼吸灯恰恰需要用户态 ioctl 控灯效；且该条与 `dmesg: addr=0x50 index=1` 一样**在当前工作区没有任何原始存档可复现**，只写在旧笔记里，按不可采信处理。
>
> 真正的功放**没有 DTS 节点**：它不需要寄存器控制，`spk-con-gpio`/`amp-en-gpio` 直接挂在 vendor 魔改的 `es8316@11` 节点上，靠两个 GPIO 使能。这与实测「手动通断 amp-en 6 次喇叭有『啪』声」完全自洽 —— 功放存在且受 amp-en 控制，只是身份不是 SN3732A。
>
> ⇒ **对音频修复零影响**：ES8316 仍是必经环节，PVDD/CPVDD 测量这条主线不变；SN3732A 从"阻塞音频的未知功放"降级为"独立的灯控外设"。

**用户已确认：原厂 Android 下喇叭能响、麦克风也能录** ⇒ **ES8316 芯片本身是好的，故障在供电/时序**，不是器件损坏。

**结论**：整条音频链目前**只能出 HDMI 声音**。但方向已明确收窄到「ES8316 的 PVDD/CPVDD 供电」这一条，具备修复条件。

## K. 传感器

| 器件 | vendor 记录 | 状态 | 实测证据 |
|---|---|---|---|
| 加速度计 KXTJ9 | `kxtj2-irq-gpio` pinctrl 组 | ❓ | IIO 下**只有 `saradc`**；全 I²C 扫描**无 0x0e/0x0f** |
| 六轴 MPU | `inv_mpu_iio` | ❓ | 同上，无 IIO 设备；总线无 0x68/0x69 |
| 磁力计 AK8963 | `ak8963-irq-gpio` pinctrl 组 | ❓ | 无 0x0c/0x0d。**注意 AK8963 常挂在 MPU 内部 I²C master 后面，主控扫描本就看不到** |
| 光感 CM3218 | `cm3218-irq-gpio` pinctrl 组 | ❓ | 无对应地址（0x10 已被 ES7243 占用） |

**证据互相矛盾，暂不下结论**：
- **支持存在**：vendor DTS 有 4 组 irq pinctrl（`ak8963` / `cm3218` / `kxtj2`）；Android `features.txt` 声明了 `accelerometer` / `compass` / `gyroscope` / `light`；11-10 那轮 vendor 扫描记录了 `sensor_register_slave:kxtj9,id=11` 与 `inv_mpu_iio: inv_mpu_init:746`。
- **支持不存在**：vendor DTS 里这 4 个**只有 pinctrl 组、没有任何 i2c 设备节点**；现网全部 I²C 总线扫描**一个地址都没扫到**。
- **可能的解释**：① 板上没焊（pinctrl 是参考设计照抄，Android feature 标志也是抄的）；② 传感器被某条 GPIO 断电，运行时不上电；③ AK8963 在 MPU 的 bypass 后面，本来就不该被扫到。

> 定论需要重刷 Android 抓一次 `dmesg | grep -iE "kxtj|mpu|ak8963|cm3218"`，或拆机看丝印。**优先级低，不建议现在投入。**

## Android 备份交叉核对（vendor DTS vs 现网）

数据源：`rk3399-mid-backup/armbian/rk3399-mid-stock.dts`（vendor 4.4.83 全量反编译，4319 行）

### 1. USB 拓扑 —— 从属关系到物理口的完整还原

| 控制器 | vendor 配置 | 物理含义 | 现网实测 |
|---|---|---|---|
| `fe900000` | `dr_mode=host`，**`phys = <usb2-phy usb3-phy>`** | **唯一的 USB 3.0 Host 口** | ✅ U 盘挂此，**5000M / 136 MB/s** |
| `fe800000` | `dr_mode=otg`，**只挂 `usb2-phy`，且 `maximum-speed="high-speed"`** | OTG 口**原厂就限在 USB 2.0** | mainline 配成 host+usb3-phy，能力虚高，物理口仍只 2.0 |
| `fe380000/fe3a0000` | EHCI + OHCI，`usbphy0` | USB 2.0 Host 通道 0 | 驱动注册（usb5/usb6） |
| `fe3c0000/fe3e0000` | EHCI + OHCI，`usbphy1` | USB 2.0 Host 通道 1 | 驱动注册（usb7/usb8） |
| 5V 供电 | `vcc5v0_host0` + `vcc5v0_host1` 均 enabled | 两个口的 VBUS | `vcc5v0_host` enabled |

> **结论**：板上一共 **1 个 USB 3.0 + 2 个 USB 2.0 + 1 个 OTG(2.0)**。
> 想跑满 3.0（5000M）**只有 `fe900000` 那个口**，插到 OTG 或 2.0 口上只能 480M。

### 2. 「有节点但没驱动」的全量核对

用 `platform 设备有 compatible 却无 driver 符号链接` 反查，结果**只有 28 个 `syscon`/`qos` 节点（syscon 本来就不需要驱动绑定）+ `regulator-vcc5v0-typec0`**。

⇒ **除了已知的 typec0 注册失败，设备树里没有任何一个外设是「有节点却没驱动」的**。这一条同时证明：
- 现网 DTS 的外设声明是完整的；
- 之前判定「无驱动」的 ES7243 / SN3732A / HR8833 / 传感器，**不是漏配了节点，而是真的没有 mainline 驱动或硬件未实装**。

### 3. SD 卡槽：软件层本来就无法证明存在

vendor DTS 给 `dwmmc@fe320000` 配的是 `supports-sd` + `cap-sd-highspeed` + 缺 `non-removable`（像可插拔），
但同时**缺 `cd-gpios`、缺 `broken-cd`**——正常可插拔卡槽必须有卡检测机制，两个都没有。
加上 `vcc_sd` `num_users=0`、`fstab` 无 sdcard 条目、Android 内核日志无任何 `mmc0` 活动。

⇒ 软件层只能证明「**按 SD 卡设计**」，证明不了 PCB 焊了卡座。**与你的实物确认完全一致：没有卡槽。**

### 4. 摄像头：原厂走的是「BSP ISP + 模组自带 ISP」，不是 V4L2

这是本清单**唯一一处曾经判错**的项，错因值得记录。

| 层面 | 原厂实现 | 说明 |
|---|---|---|
| 内核 | `/dev/camsys_marvin`、`/dev/camsys_marvin1`（misc 10:59/10:58） | Rockchip **BSP ISP 驱动（CamSys v0.34.5）**，不注册 V4L2 设备 |
| HAL | `camera.rk30board.so` | Rockchip 私有 HAL，直接与 camsys 通信 |
| 模组 | **`libisp_siliconimage_isp.so` / `libisp_silicomimageisp_api.so`** | **摄像头模组自带 Silicon Image ISP**，SDK 符号为 `Sensor_Isi*` |
| DTS | 只有 `isp@ff910000` / `isp@ff920000` + `camera-key`（ADC 按键） | **没有任何 sensor 节点**，sensor 由 HAL 运行时 I²C 探测 |
| init | `ueventd.rc` 给 `/dev/camsys_marvin*` 配 `media camera` 权限 | 佐证通路 |

**为什么之前判成「没摄像头」**：我按 V4L2 惯例去找 `/dev/video*`，而原厂这条通路**根本不产生 V4L2 节点**——`/dev/video*` 为空完全正常。叠加 vendor DTS 里也没有 sensor 节点，就误判成硬件缺失了。

**sensor 型号仍未确定**：从 `stock/system.img` 里只能看到通用 SDK 携带的一大批型号（GC0308 / GC2035 / GC2155 / HM2057 / IMX307 / NT99252 / OV13850 / OV2659 / OV2685 / OV5640 / ov14825），**这些是 SDK 的编译期支持列表，不能据此断定实际是哪颗**。要确定型号，需重刷 Android 后抓 `logcat | grep -iE "sensor|isi"`，或拆机看模组丝印。

## 复现命令

```sh
# 全部 I2C 总线占用
for b in 0 1 2 3 4 6 9; do i2cdetect -y -r $b; done

# 连接器 → CRTC 绑定
grep -E "^Connector|crtc=|fb=" /sys/kernel/debug/dri/0/state

# 供电轨
for r in /sys/class/regulator/*/; do echo "$(cat $r/name) $(cat $r/state 2>/dev/null)"; done

# 电池
cat /sys/class/power_supply/cw2015-battery/uevent

# 声卡
cat /proc/asound/cards; dmesg | grep -c es8316
```
