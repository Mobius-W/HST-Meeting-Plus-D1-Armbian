## 0. 结论先行（TL;DR）

| 入口 | 调用 | 行为 |
|---|---|---|
| 按钮 `bt_ioenable` | `IoctlHelper.Ioenable()`（`MainActivity$3:45`） | 停 |
| 按钮 `bt_ioforward` / `bt_ioreverse` | `MainActivity$1:202/223/244/255/266` | 正/反转，手动点按 |

## 2. 消费链二：会议程序 fsmeeting.apk（此前完全漏挖）

包名 `com.inpor`。核心类 **`com.android.internal.util.IoctlManager`**（上午报告零命中），两个入口：

### 2.1 入口 A：声源定位（DOA 自动转向）

```
MeetingMenuBar.smali:622  →  AudioCaptureDetectHelper.startSoundLocalization()
  → Flowable.interval(1000ms) 每秒触发  [startSoundLocalization :59-63]
  → lambda$startSoundLocalization$2 :69
      ConfDataContainer.getMicAngle()   (native, libRealAudio DOA 结果)
      angle = (int) micAngle
      if (angle == -999 || angle == 90) return    ; 无效/正前方不转
      turnAngle = angle - 90                       ; 相对正前方的偏差
      IoctlManager.getInstance().turnByAngle(turnAngle)
```

### 2.2 入口 B：手动云台摇杆

```
HomePageFragment.smali:1590  →  new LocalPATControlDialog()
  RockerView.DragListener
    dragLeft()  :81  → IoctlManager.turnLeft()   (实际调 Ioforward)
    dragRight() :87  → IoctlManager.turnRight()  (实际调 Ioreverse)
  onDestroyView :99 → IoctlManager.release()     (Ioenable 停 + destroy)
```

### 2.3 IoctlManager 的脉冲时序（★★ 决定性）

`IoctlManager.smali` 三个方法全部是「发一次 + 定时停」：

| 方法 | 动作 | 停止延迟 | 方向 |
|---|---|---|---|
| `turnByAngle(angle)` :53-64 | `Ioreverse()`（angle>0）或 `Ioforward()`（angle<=0） | `abs(sen × angle)` ms，sen=`SystemProperties.getInt("com.inpor.hstdone.sen", 0x28=40)` | 按角度符号 |
| `turnLeft()` :72-80 | `Ioforward()` | 固定 **0xf0 = 240ms** | 正转 |
| `turnRight()` :86-94 | `Ioreverse()` | 固定 **240ms** | 反转 |

`$StopHandler.handleMessage` :110-114：`setRunning(false)` → 打日志「停止转动」→ **`IoctlHelper.Ioenable()`**（=AIN1/AIN2 都拉低，惰行停）。

**关键**：即使 DOA 要求转 60 度，也只是发一次方向脉冲、持续 40×60=2400ms 后停——**没有编码器反馈、没有闭环位置控制**，纯粹靠「角度×时间」开环估算。且 `isRunning` 标志保证前一次未停完时忽略新指令。

## 3. 板上对照实验：持续通电 vs 原厂脉冲

设备：`/dev/hr8833`（10:261），ocp 读数：`/sys/devices/platform/motor/ocp`。
测试脚本：本地 `dist/audio-hp-test/ptz_pulse.py`（python3 + fcntl.ioctl，发 vendor cmd，arg 被驱动忽略）。

| 方式 | 指令序列 | ocp 结果 |
|---|---|---|
| **持续 3 秒**（11-19 上午做法） | `FWD` → sleep 3s → `STOP` | 持续期间 **ocp=1**，停后回 0 |
| **原厂 240ms 脉冲 ×5** | 每轮 `FWD` → sleep 0.24s → `STOP` → sleep 0.36s | **5 轮全程 ocp=0**，停后仍 0 |

**解读**：
- 昨天报告「原厂满速 FWD 转 3 秒 ocp 全程 1 ⇒ 过流保护 ⇒ 电机停转 ⇒ 硬件坏」——**3 秒持续满速不是原厂行为**，是测试者自行设计的时长。原厂任何一次转动都被 Handler 在 240ms~数秒内切断。
- ocp=1 只说明「持续通电触发了 HR8833 过流/短路/欠压/过温保护」，**不能推出云台硬件坏**。按手册，堵转电流也会触发 OCP——若电机已到机械限位仍持续通电，同样 ocp=1。
- 脉冲方式 ocp=0 只证明「不过流」，**不能直接证明轴转了**（也可能电机根本没动、电流小）。需要物理判据。

## 4. vendor 内核侧：确认挖尽

`kernel.img`（24MB，Linux 4.4.83）全镜像正则扫描 `hr8833|gimbal|motor|Ioenable|Ioforward|Ioreverse|ocp` → 28 条字符串，全部落在这几类：
- kallsyms 符号：`hr8833_probe/remove/open/release/ioctl/read/write`
- 调试串：`hr8833_ioctl. cmd = %d\n`（0xe2ea66）
- DTS/属性：`heroic,hr8833`(0x10df660)、`ocp-det-gpio`、`ain1/ain2/sleep-gpio`、`motor` class、`/dev/hr8833`

**没有**：额外 ioctl cmd、OCP 读取/中断、PWM、位置/编码器接口、第二个设备节点。
⇒ 11-16《云台-原厂 hr8833 ioctl 反汇编》已把驱动端挖尽，**无需再反汇编内核**。vendor DTS 属性见 `开发资料/硬件原始事实/vendor-dtb-facts.md:67`（ain1=gpio2_2、ain2=gpio2_3、sleep=gpio2_4、ocp-det=gpio2_5）。
