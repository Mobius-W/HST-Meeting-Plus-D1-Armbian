# 刷机指南

> 从原厂 Android 刷到 Armbian 的完整操作手册。命令以 `rkdeveloptool` 为准。
> **动手前必须备份全盘**，否则出错无法回退。

---

## 0. 工具准备

### 0.1 rkdeveloptool

macOS / Linux 均需从源码编译（Rockchip 官方，无预编译包）：

```bash
git clone https://github.com/rockchip-linux/rkdeveloptool.git
cd rkdeveloptool
# Ubuntu/Debian: sudo apt install libudev-dev libusb-1.0-0-dev
# macOS:         brew install libusb pkg-config
autoreconf -i && ./configure && make -j$(nproc)
sudo cp rkdeveloptool /usr/local/bin/
rkdeveloptool --version
```

### 0.2 材料清单

| 材料 | 本仓库路径 | 用途 |
|---|---|---|
| DDR loader | [`firmware/loader/rk3399_loader_v1.30.130.bin`](../firmware/loader/rk3399_loader_v1.30.130.bin) | `db` 下到 SRAM，初始化 DDR/eMMC |
| Armbian 整盘镜像 | CI 产物（见下文） | `wl 0` 写入 |
| 原厂全盘镜像 | 本地备份（[`firmware/README.md`](../firmware/README.md) 说明） | 出错回退 |
| USB-TTL 串口线 | — | 抓启动日志，波特率 1500000 8N1 |

### 0.3 获取 Armbian 镜像

镜像（约 1.7 GiB）超出 GitHub 单文件 100 MB 上限，不在本仓库。两种获取方式：

1. **自己编译**（推荐）：仓库 `.github/workflows/build-armbian.yml`，`workflow_dispatch` 触发，约 69 分钟，产物在 Actions artifact（`armbian-rk3399-mid-24.zip`）。
2. **用已发布产物**：若后续有 Release asset，从 Releases 页下载。

镜像内已包含：mainline 内核 6.18.63、rockchip-isp1 / imx307 / es7243 / hr8833 等驱动、板级 DTS。

## 1. 进 Loader 模式

**关键事实**：板载**微动按钮 = Reset**，不是 MaskROM 键。长按它再上电进的是 **Loader 模式**。

```text
彻底断电（带电池，长按电源键 15 s 放电，或拔电池排线）
  → 按住板载微动按钮
  → 插 OTG 数据线（接下载口，不是充电口）
  → 上电
  → 保持 2~3 s 后松开微动按钮
```

确认：

```bash
rkdeveloptool ld
# 应看到 USB 0x2207:0x330c，标注 Loader
```

---

## 2. Loader → MaskROM

从 Loader 模式用命令回 MaskROM：

```bash
rkdeveloptool rd 3
sleep 2
rkdeveloptool ld
# 应标注 Maskrom
```

> **坐标系纪律**（血泪教训）：
> - **MaskROM** 下 `wl 0` = 写物理 LBA 0（整盘起点）。
> - **Loader** 下 `wl 0` = 实际写到物理 LBA 8192（逻辑 0 + 8192 偏移）。
> - 所以整盘写盘前**必须**确认 `ld` 显示 `Maskrom`。若显示 `Loader` 就 `wl 0`，会破坏原厂分区表布局。

---

## 3. 下 loader 并写盘

```bash
# MaskROM 下把 DDR loader 下到 SRAM（此时设备转为 Loader，但 db 后坐标仍是物理地址）
rkdeveloptool db firmware/loader/rk3399_loader_v1.30.130.bin

# 确认
rkdeveloptool ld    # 标注 Loader（db 之后）

# 整盘写 Armbian（从 zip 解出的 .img）
unzip armbian-rk3399-mid-24.zip
rkdeveloptool wl 0 Armbian-unofficial_26.11.0-trunk_Rk3399-mid_noble_current_6.18.63_minimal.img

# 每个分区写完后应打印 Write LBA from file (100%)，返回码 0
```

> 写盘耗时约 10~20 分钟（1.7 GiB），不要中途拔线。

---

## 4. 复位与冷启动

```bash
rkdeveloptool rd       # 复位（无参数 = 正常启动，不是回 MaskROM）
```

然后：

1. **拔掉 USB 数据线**（loader 的 FlashBoot 在 USB host 在线时会优先进 rockusb，导致起不到系统）；
2. 断电 10 s；
3. 上电；
4. TTL 串口 1500000 8N1 抓日志，应看到 `DDR Version 1.30 → U-Boot → Starting kernel`。

---

## 5. 常见失败

| 症状 | 原因 | 处理 |
|---|---|---|
| `rkdeveloptool ld` 看不到设备 | 驱动没装 / 数据线是充电线 | 换数据线，接 OTG 口，装 libusb |
| 一直停在 Maskrom | eMMC 无可引导介质 / 微动按钮没松开 | 松开微动按钮，彻底冷启动 |
| 刷完又回 Maskrom | 整盘 `wl 0` 清掉了 LBA64 的 IDB | 重写 loader 区，见 CI 产物的 boot 区 |
| `wl 0` 后分区表错乱 | 在 Loader 而非 MaskROM 下写了物理 0 | 回 MaskROM 重写整盘 |
| 起不到系统但串口有输出 | USB host 仍在线 | 物理拔掉 USB 数据线再冷启动 |

## 6. 回退到原厂

```bash
# MaskROM 下下 loader
rkdeveloptool db firmware/loader/rk3399_loader_v1.30.130.bin
# 整盘写回原厂备份（7.2 GiB，本地文件，不在仓库）
rkdeveloptool wl 0 rk3399-mid-emmc-full-20261110.img
rkdeveloptool rd
```

原厂分区级救砖（只写 system + resource，约 3~5 分钟）：

```bash
rkdeveloptool wl 811008 firmware/android-stock/system.img   # 需本地大文件
rkdeveloptool wl 40960  firmware/android-stock/resource.img
rkdeveloptool rd
```

> LBA 坐标来自 [`firmware/android-stock/PARTITIONS-AUTHORITATIVE.txt`](../firmware/android-stock/PARTITIONS-AUTHORITATIVE.txt)。

## 7. 刷完后的第一步验收

```bash
# SSH 进板（默认账号 root，密码见你自己的记录；仓库不存明文口令）
uname -r                    # 6.18.63-current-rockchip64
cat /proc/asound/cards      # rk3399mides7148 + hdmisound
arecord -l                  # ES7243 麦阵
ls /dev/video5              # rkisp1 mainpath
ls /dev/hr8833              # 云台驱动
cat /sys/devices/platform/motor/irq_stat   # 云台 nFAULT 诊断
```

详细验收清单见 [`硬件清单-驱动状态-20261116.md`](硬件清单-驱动状态-20261116.md) §L.3。
