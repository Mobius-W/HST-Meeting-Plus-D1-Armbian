## 1. 一句话现状

**ALSA 采集通路已经通了（card1 / 4~8ch PCM 可录），ES7243 的 I2C 时序也已按原厂复刻并逐寄存器验证落地；
但采到的数据恒为 0xFFFF —— 即 SoC 侧 RX 在跑，数据脚上没有有效数据。**
驱动侧该做的都做了，剩下的是"ADC 到底有没有在驱动 SDOUT"这件硬件问题。

## 2. 已完成（可复现）

### 2.1 驱动形态：复合 codec，而不是"标准 es7243 codec"

原厂拓扑（反汇编 + HAL 取证）是：`es8316` codec 驱动统管播放(ES7148)与采集(2×ES7243)，
两颗 ES7243 只是裸 i2c client（DTS 无 `#sound-dai-cells`、不挂 sound card），
4 麦数据从 **i2s0 的 capture** 进系统（`es8316_pcm_startup → es7243_start`）。

mainline 的 `simple-audio-card` 一个 dai_link 只能挂一个 codec DAI，
所以"播放+采集共用 i2s0"只能由一个 DAI 同时提供两个方向 ⇒ 本驱动：

| 方向 | 内容 |
|---|---|
| playback | ES7148 直通（无寄存器，等价 es7134 的 dummy 行为） |
| capture | 4~8ch，hw_params 时给两颗 ES7243 上电+配置，shutdown 时 standby |

DTS（`armbian/userpatches/.../rk3399-mid.dts`）新增：

```dts
mic_array: mic-array {
    compatible = "rockchip,rk3399-mid-audio";
    #sound-dai-cells = <0>;
    everest,adc = <&es7243_0>, <&es7243_1>;
};
/* es7148-sound 的 codec 由 &es7148 改为 &mic_array */
```

> 该 DTS 改动**尚未提交**（本地 working tree 里），板端验证通过后再入 CI。

### 2.2 寄存器序列（原厂复刻）

```
init    : 0x00 = 0x01
start   : 0x06=0x18, 0x01=0x0c, 0x02=0x10, 0x03=0x04, 0x04=0x02,
          0x05=0x1a, 0x08=0x41(0x12 芯片 0x21), 0x07=0x80, 0x09=0x00,
          0x06=0x00, 0x05=0x13
standby : 0x06=0x05, 0x05=0x1b, 0x06=0x5c, 0x09=0x9f
```

板端 readback（start 之后，chip@0x10）：
`01 0c 10 04 02 33 00 80 41 00 55 00 12 20 40 ff`
—— 除 0x05 被芯片强制 bit5（0x13→0x33）、以及残留的 0x0A=0x55 外，全部与写入一致。

### 2.3 ★ 芯片定性与一张关键的外部证据

**板上芯片只解码寄存器地址低 4 位**（实测：写 0x28 / 0xA8 / 0x18 后都落到底 0x08；写 0x30 落到 0x00）。
⇒ 是 **16 寄存器版的 ES7243（非 E）**，ES7243E 数据手册（8 位寄存器、0x00-0x1F+）不适用。
⇒ 之前"CHIP_ID 0xFD=0x60 / 0xFE=0x40 ≠ ES7243E 的 0x7A/0x43"是**误判**：0xFD 只是 0x0D 的镜像。

原厂序列的语义由 ESPHome / ESP-ADF 的 es7243 驱动（ESP32 实测可用）反证：

| 寄存器 | 语义（ESP-ADF） | 原厂写入 |
|---|---|---|
| 0x00 | MODE_CONFIG | 0x01 |
| 0x01 | SDP_FORMAT | 0x0c |
| 0x05 | MUTE_CONTROL | 0x1a → 0x13 |
| 0x06 | STATE_CONTROL | 0x18 → 0x00 |
| 0x08 | **GAIN / ANACTRL1** | 0x10 芯片 0x41（≈24.5dB）、0x12 芯片 0x21（≈18dB） |

⇒ **`0x08` 的两颗差异不是 TDM 级联，而是麦克风增益**。此前"级联唯一的 0x08 差异"的解读需要改口径。

### 2.4 SoC 侧已排除的项（都有实测）

| 项 | 结论 |
|---|---|
| i2s0 引脚复用 | 录制时 9 个 pin（GPIO3_B0..B7 + GPIO4_A0）全部切到 `i2s0-8ch-bus` ✓ |
| MCLK | `clk_i2s0` = 12.288 MHz、enabled，pin 128 复用正常 ✓ |
| 主从 | I2S_CKR MSS=0（SoC 为 master）；TRCM 已按 bit28 验过 TXRX / TXONLY 两种 ✓ |
| bclk_ratio | 默认 64（2 槽）；已改为 `32 × channels`（4ch=128、8ch=256）✓ |
| 帧长 | CKR TSD/RSD = 63（64 BCLK/帧），2ch 16bit 对齐正确 ✓ |
| 声道数 | 2 / 4 / 8 全试过，全部恒定 0xFFFF ✗ |

### 2.5 已做的"无效"实验（避免重复走）

| 实验 | 结果 |
|---|---|
| 录制中 poke `0x00=0x80`（CSM 上电）/ `0x01=0x3c`（时钟全开） | 数据无任何变化 |
| 录制中切 TRCM TXRX ↔ TXONLY | 无变化（寄存器位确认已切） |
| 边播放 440Hz 边录（验证 RX 通路/是否读到 SoC 自己驱动的脚） | 8 声道全恒定，无 440Hz |
| ESP-ADF 最小序列（`seq_variant=1`，只写 6 个寄存器） | 仍然 0xFFFF |
| 2ch / 4ch / 8ch，S16 / S32 | 全部恒定 |

## 3. 结论与待办（按优先级）

**现象定性**：采集 DMA 正常、时钟正常、寄存器写入生效，但 SDI 上读到恒定位 1。
⇒ 要么 ADC 没在驱动 SDOUT，要么 SDOUT 没接到 SoC 采的那几根脚。
软件侧已无更多可调项，必须靠硬件观测定位。

### 待办 1（最优先）：量 ADC 的 SDOUT（pin 3）
录着音时用示波器/逻辑分析仪看两颗 ES7243 的：
- pin 20 MCLK 是否有 12.288 MHz（若没有 → ADC 时钟网络与 ES7148 的 CLKIN 不是同一根）
- pin 6 SCLK / pin 7 LRCK 是否有 64fs / 48kHz（若是死线 → 时钟没到 ADC）
- pin 3 SDOUT 是否有数据（若一直高 → ADC 没启动；若有数据 → 问题在 SoC 侧 pad/GRF）

只有万用表时：SDOUT 若在"静音/有声"两种状态下电压有差，即说明它在驱动。

### 待办 2：确认麦阵物理连接
硬件清单里写的是"双麦阵列"，而两颗 ES7243 是 4 路输入 ⇒ 确认 4 个麦（或麦板排线）是否都接在该板上。

### 待办 3：与原厂运行时状态对比
若上面两项都不便，最彻底的办法是把原厂 Android 刷回去（或用 eMMC 里的 stock 分区启动），
在它录音时 `i2cdump` 两颗 ES7243 的 16 个寄存器，与我们的 readback 逐字节对比。

### 待办 4（软件侧收尾，与硬件并行）
- 用自写 machine driver 替代 simple-audio-card，正规设置 `dai_link->symmetric_rate`
  与 `bclk_ratio`（现在是在 codec 侧 hw_params 里改 rtd->dai_link / cpu dai 的临时做法）。
- 确认 4ch 时两颗 ADC 的声道映射（哪颗 → ch0/1、ch2/3），再决定是否需要 TDM 级联。
- `seq_variant` / `trcm_txonly` / `auto_bclk_ratio` / `power_on_probe` / `dump_regs`
  这几个实验参数最终应删掉或收敛成默认行为。

## 4. 复现路径（板端）

```bash
# 1) 模块（CI: Build out-of-tree modules，约 2 分钟）
#    产物 ko-rk3399-mid-<run>.zip 内 kernel-modules/es7243/es7243.ko
scp es7243.ko root@10.26.88.10:/root/

# 2) dtb 手术（免重编内核，板端 dtc 即可）
cp /boot/dtb/rockchip/rk3399-mid.dtb /boot/dtb/rockchip/rk3399-mid.dtb.bak-$(date +%H%M)-premic
dtc -I dtb -O dts -o /tmp/cur.dts /boot/dtb/rockchip/rk3399-mid.dtb
python3 /tmp/patch-dtb-micarray.py /tmp/cur.dts /tmp/new.dts
dtc -I dts -O dtb -o /tmp/new.dtb /tmp/new.dts
cp /tmp/new.dtb /boot/dtb/rockchip/rk3399-mid.dtb && sync && systemctl reboot

# 3) 加载与测试
insmod /root/es7243.ko            # 可选 seq_variant=1 / trcm_txonly=0 / power_on_probe=1
arecord -l                        # card 1 应有 capture device
arecord -D hw:1,0 -c 4 -f S16_LE -r 48000 -d 3 /tmp/t4.wav
dmesg | grep mid-audio            # start/standby 时的寄存器 dump
```

回退：把 `/boot/dtb/rockchip/rk3399-mid.dtb.bak-*` 覆盖回去即可（不涉及内核与 eMMC）。
